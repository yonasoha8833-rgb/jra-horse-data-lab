# JRA HORSE DATA LAB

スマートフォン向けJRA公式成績データ分析プロジェクト。

馬別成績の検索・集計、条件別成績、最大3頭の条件別比較、近5走の推移表示、レース単位の結果一覧・上位成績表示、公式PDFの初期取り込み処理を実装しています。実際の公式PDFでの抽出精度検証とデータ蓄積は継続中です。ラップ・調教データの本格的な構造化は未実装です。

JRA公式のレースラップはレース全体のラップであり、各馬個別の1Fラップではありません。推定値と実測値を区別します。

## 馬別集計モジュール（追加）

`race_analysis.py` は、PDF抽出処理が出力したレース結果レコードを馬名単位で集計します。 `summarize_races` はPDF URL・開催日・競馬場・レース番号で出走馬レコードをまとめ、出走記録数、着順記録数、着順なしの数、勝ち馬（複数の1着がある場合は全頭）、勝ち時計（勝ち馬が1頭のときのみ）、上位3着、レース全体の上がり3F・ラップ、検証警告を返します。 `summarize_race_conditions` はレースを重複カウントせず、競馬場・芝/ダート・距離帯・馬場状態ごとにレース数、平均出走記録数、平均勝ち時計、平均レース上がり3F、警告レース数を集計します。標準では3レース未満の条件を除外し、勝ち時計・上がり3Fは値が確認できたレースだけで平均します。画面の「条件別レース傾向」から集計軸を切り替えられます。レース番号がない行は安全にグループ化できないため除外します。画面の「レース別成績」には新しい順で最大20レースを表示し、レースごとの詳細を開いて上位成績やラップを確認できます。

### 入力レコードの主なキー

- `horse_name`: 馬名（必須）
- `horse_registration_number`: JRA等の公式登録番号（取得できる場合）。馬別集計はこの番号を優先し、未取得時は馬名による仮集計として扱います。
- `date`: 開催日（YYYY-MM-DD）
- `track`: 競馬場
- `surface`: 芝・ダート
- `distance`: 距離（m）
- `finish`: 着順（着順を付与できない場合は `null`）
- `result_status`: 公式PDFの行末で確認できた結果状態（競走中止・失格・中止・取消・除外など）
- `declared_field_size`: PDFに記載された出走頭数（読み取れた場合）
- `race_validation_warnings`: 馬番重複・記載頭数との不一致などの検証警告
- `finish_time_seconds`: 走破タイム（秒、公式PDF取り込み形式）
- `individual_last3f`: 個別馬の上がり3F（公式値がある場合のみ）
- `race_last3f`: レース全体の上がり3F（個別馬の値とは別項目）
- `time_seconds` / `last3f`: 旧形式データとの互換用キー
- `corner_positions`: コーナー通過順位
- `jockey`: 騎手

欠損値や数値に変換できない値は平均計算から除外し、推測で補完しません。馬別集計には出走数・着順記録数・着順なしの走数・結果状態別件数も含まれます。画面では馬名・競馬場・芝/ダート・距離による絞り込みと、出走数・勝利数・勝率・参考指数による並べ替えができます。各馬カードには競馬場別、馬場状態別、芝/ダートと距離の組み合わせ別、競馬場・コース・距離別に、出走数・勝利数・勝率・複勝回数を折りたたみ表示します。全体勝率との差が15ポイント以上の条件は「得意傾向」「苦手傾向」として表示しますが、各条件3走未満では判定しません。分析エンジンの `summarize_conditions` も最低出走数を指定して小標本を除外できます。 距離適性は短距離（1000〜1400m）、マイル（1401〜1800m）、中距離（1801〜2200m）、長距離（2201〜5000m）の4区分でも確認できます。コース（芝/ダート）と馬場状態の組み合わせも表示します。距離帯は画面上の整理用区分であり、公式の距離分類を示すものではありません。Python側の `distance_band` と `summarize_distance_bands` でも同じ区分を使用し、3走未満の区分は標準で除外します。これらは過去成績の説明的な集計で、将来の着順を予測するものではありません。比較対象に最大3頭を選ぶと、全取り込み記録を使って出走数・勝利数・勝率・複勝率・参考指数を横並びで比較できます。比較表では全成績のほか、距離帯（短距離・マイル・中距離・長距離）、芝/ダート、馬場状態、芝/ダートと馬場状態の組み合わせを選び、同じ条件に該当する記録だけで比較できます。条件に該当する記録がない馬は数値を表示せず「—」とし、データのない条件を推測で補いません。 各馬カードでは近5走の着順・日付・競馬場を時系列で表示し、直近3走とその前3走の平均着順を比較します。6走分の着順データがない場合は傾向を断定しません。分析エンジンの `recent_form_summary` でも同じ比較を行えます。着順なしには中止等のほか、抽出できなかった行も含まれるため、必ずしも全件が競走中止を意味するわけではありません。

### 利用例

```python
import json
from race_analysis import summarize_horses, filter_records

with open("data/race_results.json", encoding="utf-8") as f:
    records = json.load(f)

tokyo_mile = filter_records(records, track="東京", surface="芝", distance=1600)
print(json.dumps(summarize_horses(tokyo_mile), ensure_ascii=False, indent=2))
```

## JRA公式PDFの馬別データ取り込み

レース見出しの天候表記（晴・曇・雨・小雨・小雪・雪）に続く馬場状態（良・稍重・重・不良）を `going` として抽出します。表記が確認できない場合は推測せず `null` にします。

PDF本文の読み取りには Poppler の `pdftotext` を使用します。ローカル環境では Poppler をインストールしたうえで実行してください。

```bash
python -m unittest discover -s tests -v
python import_results.py --limit 1
```

GitHub上では Actions → **Import JRA race results** → Run workflow から実行できます。最初は1 PDFずつ取り込んで抽出結果を確認してください。入力の `limit` を増やすと複数PDFを処理します。

取り込み先は `data/race_results.json` です。画面の「データ品質の詳細を表示」から、集計レース数、警告レース数、馬番重複、頭数不一致、日付・競馬場・距離・走破タイムの欠損、不正な走破タイムを確認できます。品質レポートは警告フィールドが欠損・不正形式の場合も安全に集計します。重複取り込みはPDF URL・競走番号・馬番で抑制します。`import_failures` には失敗URL・試行回数・最終試行日時・エラー内容を保存し、失敗または抽出0件のPDFは処理済みにせず次回実行で再試行します。`quality_report` には競走数・検証警告のある競走数・馬番重複・頭数不一致・日付/競馬場/距離/馬場状態/走破タイムの欠損件数と、秒数が不正な走破タイムの件数を集計します。未試行PDFを失敗済みPDFより優先するため、1件の失敗が後続PDFの取り込みを妨げません。Actionsの取り込み処理は、PDFを取得する前にユニットテストを実行します。

### データ精度に関する注意

- 着順は走破タイムを抽出できた馬行の掲載順で付与します。タイムがない馬行は着順を `null` とし、後続馬の着順をずらしません。行末に明記された「中止」「競走中止」「失格」「取消」「除外」は `result_status` に保存し、失格等にタイムが記載されていても着順を付与しません。馬主名などの途中に同じ文字列が含まれるだけでは状態と判定しません。同着・取消・除外などの詳細な区別は今後の検証対象です。
- `race_last3f` はレース全体の上がり3Fです。個別馬の上がり3Fではありません。
- `individual_last3f` は公式資料から個別値を確認できるまで `null` のままです。
- 距離は `ｍ`・`m`・`メートル` の単位表記を伴う数値だけを採用し、1,000〜5,000mの範囲外は欠損扱いにします。開催年などの数字を距離と誤認しないようにしています。開催日は年・月・日の実在する暦日か検証し、2月30日などは欠損扱いにします。馬行は枠番1〜8、馬番1〜18、年齢2〜20歳の範囲外を除外し、文字抽出の異常値が集計に混ざらないようにします。レース番号は1〜12のみ採用します。走破タイムの秒部分が60以上の場合はタイムを欠損扱いにして `runner_validation_warnings` に記録します。レース内の馬番重複や、PDF記載頭数と抽出馬行数の不一致は `race_validation_warnings` に記録し、元の行は確認用に保持します。初期パーサーは基本項目を抽出する段階です。全競馬場・全ページでの精度検証後に本格集計へ接続します。
