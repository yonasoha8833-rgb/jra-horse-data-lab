# JRA HORSE DATA LAB

スマートフォン向けJRA公式成績データ分析プロジェクト。

馬別成績の検索・集計、条件別成績、最大3頭の条件別比較、近5走の推移表示、レース単位の結果一覧・上位成績表示、公式PDFの初期取り込み処理を実装しています。実際の公式PDFでの抽出精度検証とデータ蓄積は継続中です。ラップ・調教データの本格的な構造化は未実装です。

JRA公式のレースラップはレース全体のラップであり、各馬個別の1Fラップではありません。推定値と実測値を区別します。

## 馬別集計モジュール（追加）

`race_analysis.py` は、PDF抽出処理が出力したレース結果レコードを馬名単位で集計します。 `summarize_races` はPDF URL・開催日・競馬場・レース番号で出走馬レコードをまとめ、出走記録数、着順記録数、着順なしの数、勝ち馬（複数の1着がある場合は全頭）、勝ち時計（勝ち馬が1頭のときのみ）、上位3着、レース全体の上がり3F・ラップ、検証警告を返します。 `summarize_horse_condition_profiles` は登録番号（未取得時は馬名）で馬を識別し、競馬場・芝/ダート・距離帯・馬場状態・コースと馬場状態の組み合わせ・競馬場とコースと距離の組み合わせごとに各馬の成績を返します。標準では各条件3走未満を除外し、欠損条件は推測で補いません。`summarize_race_conditions` はレースを重複カウントせず、競馬場・芝/ダート・距離帯・馬場状態ごとにレース数、平均出走記録数、平均勝ち時計、平均レース上がり3F、警告レース数を集計します。標準では3レース未満の条件を除外し、勝ち時計・上がり3Fは値が確認できたレースだけで平均します。画面の「条件別レース傾向」から集計軸を切り替えられます。レース番号がない行は安全にグループ化できないため除外します。画面の「レース別成績」には新しい順で最大20レースを表示し、レースごとの詳細を開いて上位成績やラップを確認できます。

### 入力レコードの主なキー

- `horse_name`: 馬名（必須）
- `horse_registration_number`: JRA等の公式登録番号（取得できる場合）。馬別集計はこの番号を優先し、未取得時は馬名による仮集計として扱います。
- `date`: 開催日（YYYY-MM-DD）
- `track`: 競馬場
- `surface`: 芝・ダート
- `distance`: 距離（m）
- `finish`: 着順（着順を付与できない場合は `null`）
- `result_status`: 公式PDFの行末で確認できた結果状態（競走中止・失格・中止・取消・除外など）
- `declared_field_size`: PDFに記載された出走頭数（読み取れた場合）
- `race_validation_warnings`: 馬番重複・記載頭数との不一致などの検証警告
- `finish_time_seconds`: 走破タイム（秒、公式PDF取り込み形式）
- `individual_last3f`: 個別馬の上がり3F（公式値がある場合のみ）
- `race_last3f`: レース全体の上がり3F（個別馬の値とは別項目）
- `time_seconds` / `last3f`: 旧形式データとの互換用キー
- `corner_positions`: コーナー通過順位
- `jockey`: 騎手

欠損値や数値に変換できない値は平均計算から除外し、推測で補完しません。馬別集計には出走数・着順記録数・着順なしの走数・結果状態別件数も含まれます。画面では馬名・競馬場・芝/ダート・距離による絞り込みと、出走数・勝利数・勝率・参考指数による並べ替えができます。各馬カードには競馬場別、馬場状態別、芝/ダートと距離の組み合わせ別、競馬場・コース・距離別に、出走数・勝利数・勝率・複勝回数を折りたたみ表示します。全体勝率との差が15ポイント以上の条件は「得意傾向」「苦手傾向」として表示しますが、各条件3走未満では判定しません。分析エンジンの `summarize_conditions` も最低出走数を指定して小標本を除外できます。 距離適性は短距離（1000〜1400m）、マイル（1401〜1800m）、中距離（1801〜2200m）、長距離（2201〜5000m）の4区分でも確認できます。コース（芝/ダート）と馬場状態の組み合わせも表示します。距離帯は画面上の整理用区分であり、公式の距離分類を示すものではありません。Python側の `distance_band` と `summarize_distance_bands` でも同じ区分を使用し、3走未満の区分は標準で除外します。これらは過去成績の説明的な集計で、将来の着順を予測するものではありません。比較対象に最大3頭を選ぶと、全取り込み記録を使って出走数・勝利数・勝率・複勝率・参考指数を横並びで比較できます。比較表では全成績のほか、距離帯（短距離・マイル・中距離・長距離）、競馬場、芝/ダート、具体的な距離、馬場状態、芝/ダートと馬場状態、競馬場・コース・距離の組み合わせを選び、同じ条件に該当する記録だけで比較できます。選択した馬の実データに存在する条件を比較欄へ自動表示します。条件に該当する記録がない馬は数値を表示せず「—」とし、データのない条件を推測で補いません。 各馬カードでは近5走の着順・日付・競馬場を時系列で表示し、直近3走とその前3走の平均着順を比較します。6走分の着順データがない場合は傾向を断定しません。分析エンジンの `recent_form_summary` でも同じ比較を行えます。着順なしには中止等のほか、抽出できなかった行も含まれるため、必ずしも全件が競走中止を意味するわけではありません。

### 利用例

```python
import json
from race_analysis import summarize_horses, filter_records

with open("data/race_results.json", encoding="utf-8") as f:
    records = json.load(f)

tokyo_mile = filter_records(records, track="東京", surface="芝", distance=1600)
print(json.dumps(summarize_horses(tokyo_mile), ensure_ascii=False, indent=2))
```

## 重賞PDFの一覧取得と取り込み

`jra_replay_catalog.py` はJRAの年度別重賞一覧ページからレース結果リンクを抽出し、リンク先がHTMLの場合はそのページ内のPDFリンクまでたどって、PDFのURLと開催日・レース名・競馬場・コース・距離を収集します。対象は2002年以降です。例：

```bash
python jra_replay_catalog.py --from-year 2025 --to-year 2026
python import_replay_results.py --limit 1
```

重賞PDFの馬別結果は `data/replay_results.json` に年度別全成績とは分けて保存します。これにより異なるPDF由来の同一レース記録を不用意に二重登録しません。画面読み込み時に開催日・競馬場・馬番・馬名が一致する既存記録へ個別上がり3Fとコーナー通過順位を補い、一致しない記録は重賞PDF由来の記録として追加表示します。GitHub Actions の **Import JRA graded-race replay results** から年度範囲と1回のPDF処理上限を指定して実行できます。最初は1件ずつ実行し、抽出結果を確認してください。

## JRA重賞レース結果PDF（個別上がり3F）

JRAの「レース成績データ」に掲載される重賞レース結果PDFには、馬ごとの「上り（600㍍）」とコーナー通過順位が掲載されています。年度別全成績PDFのレース全体の上がりとは別の値です。専用の `jra_replay_parser.py` を追加し、重賞レース結果PDFの馬別欄から馬番・馬名・性齢・個別上がり3F・コーナー通過順位（2〜4地点の通過順）を抽出できるようにしました。開催日・競馬場・コース・距離・馬場状態はPDF本文から読み取り、レース番号・レース名など一覧側の情報は `race_metadata` で補えます。

この解析器には、改行された行と実際の成績表に近い1行形式を想定した単体テストを追加しています。PDF取り込み時はダウンロード内容の先頭がPDF署名（`%PDF-`）であることと、極端に短いファイルでないことを確認してから `pdftotext` に渡し、アクセス拒否HTMLなどをPDFとして誤処理しないようにしています。 重賞PDFのダウンロードは20MiBを上限とし、`Content-Length` がない応答も上限を超えて読み込まないようにしています。さらに、馬番・着順・馬名・個別上がり3Fの値を検証し、不正な行を含むPDFは処理済みにせず再試行対象に残します。馬番が欠けた既存行は重複キーとしてまとめず、別行のまま保持します。重賞PDF一覧の自動収集、別ファイルへの取り込み、画面での既存記録への照合も追加しました。ただし、公開PDFそのものをGitHub Actionsでダウンロードして行う実データ検証、重賞以外を含む全レースへの拡張はまだ未完了です。登録番号はこの結果表にもないため、別の公式競走馬情報から取得する必要があります。

## JRA公式PDFの馬別データ取り込み

レース見出しの天候表記（晴・曇・雨・小雨・小雪・雪）に続く馬場状態（良・稍重・重・不良）を `going` として抽出します。表記が確認できない場合は推測せず `null` にします。

PDF本文の読み取りには Poppler の `pdftotext` を使用します。ローカル環境では Poppler をインストールしたうえで実行してください。

```bash
python -m unittest discover -s tests -v
python import_results.py --limit 1
```

GitHub上では Actions → **Import JRA race results** → Run workflow から実行できます。最初は1 PDFずつ取り込んで抽出結果を確認してください。入力の `limit` を増やすと複数PDFを処理します。

取り込み先は `data/race_results.json` です。画面の「データ品質の詳細を表示」から、集計レース数、警告レース数、馬番重複、頭数不一致、日付・競馬場・距離・走破タイムの欠損、不正な走破タイムを確認できます。品質レポートは警告フィールドが欠損・不正形式の場合も安全に集計します。重複取り込みはPDF URL・競走番号・馬番で抑制します。`import_failures` には失敗URL・試行回数・最終試行日時・エラー内容を保存し、失敗または抽出0件のPDFは処理済みにせず次回実行で再試行します。`quality_report` には競走数・検証警告のある競走数・馬番重複・頭数不一致・日付/競馬場/距離/馬場状態/走破タイムの欠損件数と、秒数が不正な走破タイムの件数に加え、個別上がり3Fと競走馬登録番号の取得件数・欠損件数を集計します。未試行PDFを失敗済みPDFより優先するため、1件の失敗が後続PDFの取り込みを妨げません。Actionsの取り込み処理は、PDFを取得する前にユニットテストを実行します。

### データ精度に関する注意

- 着順は走破タイムを抽出できた馬行の掲載順で付与します。タイムがない馬行は着順を `null` とし、後続馬の着順をずらしません。行末に明記された「中止」「競走中止」「失格」「取消」「除外」は `result_status` に保存し、失格等にタイムが記載されていても着順を付与しません。馬主名などの途中に同じ文字列が含まれるだけでは状態と判定しません。同着・取消・除外などの詳細な区別は今後の検証対象です。
- `race_last3f` はレース全体の上がり3Fです。個別馬の上がり3Fではありません。
- `race_last3f` は年度別全成績PDFに記載されたレース全体の上がり3Fです。個別馬の `individual_last3f` は、JRAの重賞レース結果PDFにある馬別「上り（600㍍）」欄から専用パーサーで取得します。年度別全成績PDFのレース全体の値を個別馬に転用しません。`horse_registration_number`（競走馬登録番号）も年度別全成績PDFからは取得できないため、公式競走馬情報など別のデータ源を調査します。
- 距離は `ｍ`・`m`・`メートル` の単位表記を伴う数値だけを採用し、1,000〜5,000mの範囲外は欠損扱いにします。開催年などの数字を距離と誤認しないようにしています。開催日は年・月・日の実在する暦日か検証し、2月30日などは欠損扱いにします。馬行は枠番1〜8、馬番1〜18、年齢2〜20歳の範囲外を除外し、文字抽出の異常値が集計に混ざらないようにします。レース番号は1〜12のみ採用します。走破タイムの秒部分が60以上の場合はタイムを欠損扱いにして `runner_validation_warnings` に記録します。レース内の馬番重複や、PDF記載頭数と抽出馬行数の不一致は `race_validation_warnings` に記録し、元の行は確認用に保持します。初期パーサーは基本項目を抽出する段階です。全競馬場・全ページでの精度検証後に本格集計へ接続します。
